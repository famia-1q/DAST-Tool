Testing Methodology & Frameworks

iSeeWaves employs industry-standard methodologies to ensure comprehensive and repeatable security assessments. The following frameworks guided this assessment:

OWASP Testing Framework

The Open Web Application Security Project (OWASP) Testing Framework provides a structured approach to web application security testing. It covers information gathering, configuration management, identity management, authorization testing, session management, input validation, error handling, cryptography, business logic, and client-side testing.

Penetration Testing Execution Standard (PTES)

PTES is a comprehensive guideline for conducting penetration tests. It includes seven major sections: Pre-engagement Interactions, Intelligence Gathering, Threat Modeling, Vulnerability Analysis, Exploitation, Post Exploitation, and Reporting. This assessment adhered to the Intelligence Gathering, Vulnerability Analysis, and Reporting phases of PTES.

The CIA Triad

All findings were evaluated based on their impact on the CIA Triad:

  • Confidentiality: Ensuring that information is not disclosed to unauthorized individuals, entities, or processes.
  • Integrity: Ensuring that information is accurate, complete, and has not been modified by unauthorized parties.
  • Availability: Ensuring that information and systems are accessible and usable upon demand by authorized users.

Comprehensive CVSS v3.1 Scoring System

The Common Vulnerability Scoring System (CVSS) v3.1 is used to communicate the characteristics and severity of software vulnerabilities. The Base Score is calculated from two sets of metrics: Exploitability and Impact.

Exploitability Metrics

MetricDescription
Attack Vector (AV)Reflects the context by which vulnerability exploitation is possible (Network, Adjacent, Local, Physical).
Attack Complexity (AC)Describes the conditions beyond the attacker's control that must exist to exploit the vulnerability (Low, High).
Privileges Required (PR)Describes the level of privileges an attacker must possess before successfully exploiting the vulnerability (None, Low, High).
User Interaction (UI)Captures the requirement for a user, other than the attacker, to participate in the successful compromise (None, Required).

Remediation Summary

As a result of this assessment there are several opportunities for {{ client_name }} to strengthen its security posture. Remediation efforts are prioritized below starting with those that will likely take the least amount of time and effort to complete.

Short Term (Immediate Action - 0-14 Days)

  • Review all High and Medium severity findings from engine outputs.
  • Address critical misconfigurations and hardcoded secrets immediately.
  • Rotate any exposed credentials or API keys identified in the scan.
  • Apply emergency patches to vulnerable components if identified.

Medium Term (30-60 Days)

  • Integrate automated DAST scanning into the CI/CD pipeline.
  • Configure severity-based gating to block builds with High/Critical vulnerabilities.
  • Implement strict least-privilege access controls and secure compilation flags (e.g., ASLR, DEP, PIE).
  • Conduct a manual code review for areas flagged by automated tools.

Long Term (Strategic - 6+ Months)

  • Perform ongoing internal vulnerability assessments and code reviews.
  • Establish continuous compliance monitoring aligned with National CERT SSDLC and OWASP standards.
  • Conduct regular security awareness training for development teams.
  • Implement a comprehensive Vulnerability Management Program (VMP).
